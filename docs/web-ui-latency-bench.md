# 网页近实时波形的时延边界实测（ZDS1104）

日期：2026-09-28。目的：评估"浏览器近实时看示波器波形"在本项目环境下的可行帧率，
回答两个问题——是否支持 10 Hz；最高支持多少。测试方法与结论供 web 后端
（长连接 session + WebSocket 推送）设计直接引用。

## 测试环境

| 项 | 值 |
|---|---|
| 仪器 | ZLG ZDS1104，固件 1.2.67（已过 conformance） |
| 地址 | 192.168.138.14:5025，主机 192.168.138.10 同 /24 网段，tracert 单跳直达 |
| 仪器状态 | RUN 态，EDGE 触发，AUTO sweep；MDEP 初始为 AUTO 耦合值 3.5M（250 MSa/s） |
| 测试路径 | 本仓库传输层与驱动（`ScpiLan` / `open_scope()`），非独立实现 |
| 脚本 | `scripts/bench_latency.py`（只读为主，仅 MDEP 扫描会改配置并在退出时恢复） |

## 测量定义

- **库路径**：`scope.read_waveform("CHAN1", "NORMal")`，即现有传输层的
  connection-per-call 模型——每帧新建 TCP 连接 + I/O + WFM 解析。
- **长连接路径**：单 TCP socket 上背靠背 `:GLOBal:MULTiwave? SCREen,CHANnel1`
  （TCP_NODELAY，帧尾 CRLF 精确收取）。这是 web 后端应采用的传输方式，
  也是仪器/网络的时延地板。ZDS1104 的 `SCREen` 返回全量内存（= MDEP 点数，
  8-bit/点），帧大小随 MDEP 线性变化，因此按 MDEP 档位扫描。

## 结果

**连接与命令（connection-per-call，仪器闲时）**

| 测项 | p50 | 尖峰 |
|---|---|---|
| TCP connect（×5，多轮） | 12–30 ms | **≈1.0–1.04 s**（仪器忙时，见"归因"） |
| `*IDN?` ×10 | 15–28 ms | 47 ms（闲）/ **1057 ms**（忙轮） |

**帧率 × MDEP（长连接路径为主）**

| MDEP | 每帧字节 | 长连接 p50 | 长连接 min | 折算帧率 | 库路径 p50 |
|---|---|---|---|---|---|
| 3.5M（AUTO 耦合默认） | 3.5 MB | 841 ms | — | **1.2 fps** | 1309–1362 ms |
| 700K | 700 KB | 241 ms | — | 4.2 fps | 504 ms |
| 140K | 140 KB | 92 ms | 49 ms | **10.9 fps** | 360–389 ms |
| 14K | 14.5 KB | 39 ms | 23 ms | **≈25 fps** | 250–293 ms |

（长连接 n=3~15/档；帧内偶发尖峰 0.6–0.7 s，见"归因"。）

**上位机侧**：序列化基准未跑完（两轮脚本均在更早步骤中断），按点数线性估算
14K 帧 JSON/二进制序列化在 5 ms 量级，占 39 ms 帧预算可忽略——**估算值，
实现 web 后端时需实测确认**。

## 结论（性能边界）

1. **10 Hz 可达，条件有二**：传输必须用长连接（库现状 connection-per-call
   最快 3.7 fps，且忙时新建连接要吃 ~1 s 的 SYN 重排尖峰）；
   MDEP 必须 ≤140K。140K 档 p50=92 ms 贴线 100 ms 预算且有偶发尖峰，
   稳妥承诺用 14K 档（39 ms，余量足）或目标定 8 Hz。
2. **上限**：中位口径 ≈25 fps（14K 档），协议地板 23 ms/帧（≈43 fps）。
   工程承诺建议 ≤15–20 fps。
3. **降 MDEP 的代价**：采样率联动下降（3.5M→250 MSa/s，700K→50 MSa/s，
   14K 档更低），对"看波形形状"足够，对细节观察是 trade-off——
   web 页面必须把"MDEP 降档"作为 caveat 显示（与 MCP 工具输出同源）。
4. **DS1104Z 未测**（无 IP）。NORMal 模式每帧仅 ~1200 点，理论上限更高；
   用同脚本 `--model RIGOL_DS1104Z --port 5555` 可补测，数据并入本文档。

## 协议坑（web 后端实现必须处理，均实测确认）

1. **连接建立贵且不稳**：忙时 accept 阻塞至 ~1 s（≈TCP SYN 重传间隔）。
   流式场景必须持有长连接——即 `transport/scpi_lan.py` docstring 预留的
   P4 `bench_session` 抽象。
2. **帧尾 `\r\n` 延迟到达**：payload 后的尾部最晚 0.42 s+ 才到。长连接需先
   探明尾巴长度（首帧用 ≥0.6 s 窗口探测一次）再逐帧精确收取，否则下一帧
   4 字节长度前缀错位、流崩（测试第一版即崩于此）。
3. **MDEP 变更后空块窗口**：`SCREen` 连续返回空块数秒（曾一次 >12 s 未恢复、
   未复现）。实现需重试 + 降级，配置变更后先预热一帧再进流。
4. **恢复配置要写 `AUTO`**：AUTO 耦合出的实际值（如 3.5M）不在合法阶梯内，
   直接写数值会被仪器忽略。
5. **轮询与 MCP 互斥**：SCPI 服务单线程，流式轮询期间其他客户端命令排队，
   web 后端须与 MCP 工具调用共享传输层互斥锁或暂停轮询让行。

## 阻塞归因（推测，待验证）

观测尖峰的来源判断为**仪器固件的网络服务实现**（单线程 SCPI、小 backlog、
忙轮询），而非通讯线路：

- ping 稳定 11–12 ms、零丢包；3.5 MB 大帧能按稳定节奏完成——线路无丢包、
  无带宽瓶颈迹象；
- 尖峰呈离散排队特征：connect/IDN 的 ~1 s 与 SYN 重传间隔吻合（忙时
  accept 不及），帧内 0.6–0.7 s 疑似固件内部任务抢占；连续抖动才是链路
  问题的典型模式；
- `*IDN?` 变慢与空块重试同轮出现（命令在仪器端排队）；
- 反常点：同网段单跳 ping 应 <1 ms，实测 11–12 ms——要么中间桥接/交换
  设备慢，要么仪器 ICMP 响应本身慢，未区分。

待验证检查（按区分度排序）：双机对照 ping（一台跑帧循环、另一台 ping 仪器，
定位阻塞层级）；网线直连绕过交换机（判 11 ms 底噪归属）；DS1104Z 同链路
对照。对实现的含义不因归因而变：长连接 + 尖峰容忍（跳帧不排队、渲染永远
用最新帧）。

## 复现

```bash
# ZDS1104（会短暂改 MDEP 并在退出时恢复为 AUTO）
SCOPE_MCP_HOST=192.168.138.14 SCOPE_MCP_MODEL=ZLG_ZDS1104 \
  conda run -n oscScope-mcp python scripts/bench_latency.py

# DS1104Z（RIGOL 分支含 IEEE 块长连接，待真机验证）
SCOPE_MCP_HOST=<ip> SCOPE_MCP_MODEL=RIGOL_DS1104Z \
  conda run -n oscScope-mcp python scripts/bench_latency.py --port 5555
```
